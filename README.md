# Cafe POS — прототип

Локальная система для кафе: официанты (планшеты), кухня (экран поваров), админка.
Работает полностью локально, без интернета — сервер поднимается на компьютере в кафе,
все устройства заходят на него через Wi‑Fi.

Зависимостей нет — используется только встроенный Node.js. Ничего через `npm install`
ставить не нужно.

## Запуск на компьютере в кафе (сервер)

1. Установите Node.js (версия 18 или новее) с https://nodejs.org — один раз.
2. Скопируйте папку `cafe-pos` на этот компьютер.
3. Откройте терминал/командную строку в этой папке и выполните:

   ```
   node server/server.js
   ```

   Увидите сообщение вида:
   ```
   Cafe POS сервер запущен: http://localhost:3000
   ```

4. Чтобы сервер не завершался при закрытии терминала и запускался автоматически
   при включении компьютера — это можно настроить отдельно (диспетчер задач Windows /
   `pm2` / автозагрузка), когда прототип будет обкатан. Для теста достаточно держать
   окно терминала открытым.

## Узнать локальный IP этого компьютера

- **Windows**: `ipconfig` → строка "IPv4-адрес" (например `192.168.1.50`).
- **macOS**: Системные настройки → Wi‑Fi → Подробнее → IP-адрес.
- **Linux**: `hostname -I` или `ip addr`.

Все планшеты и телефоны должны быть подключены к **той же Wi‑Fi сети**, что и сервер.

## Вход с планшетов/телефонов официантов и кухни

В браузере (Chrome/Safari) откройте:

```
http://<IP-компьютера-сервера>:3000
```

например `http://192.168.1.50:3000`. Дальше — выбрать роль (Официант / Кухня / Админ).

Совет: на планшете официанта сразу поставьте эту страницу на "домашний экран"
(в Chrome: меню → "Добавить на главный экран") — будет открываться как отдельное
приложение, без адресной строки.

## Стартовые данные для входа (обязательно смените перед реальной работой)

- Официант «Анна»: PIN `1111`
- Официант «Игорь»: PIN `2222`
- Админка: пароль `admin123` (сменить в разделе Настройки после первого входа)

## Что уже работает

- Официант: вход по PIN, выбор стола, добавление позиций из меню, отправка на кухню,
  просмотр статуса готовности, закрытие заказа и чек (печать через диалог печати браузера).
- Кухня: список активных заказов в реальном времени (обновление раз в 3 секунды),
  отметка готовности по каждой позиции.
- Админка: категории и позиции меню (добавить/изменить/скрыть/удалить), официанты,
  столы, выручка за сегодня по официантам, месячный отчёт (по дням, по официантам,
  топ позиций) с выгрузкой в CSV.

## QR-меню для гостей

Гости сканируют QR-код на столе и листают меню на своём телефоне: фото, описания и
цены блюд, без возможности заказать.

- Адрес меню: `http://<IP-компьютера-сервера>:3000/menu`.
- Админка → **«QR-меню для гостей»**: название, логотип, приветствие, контакты, валюта,
  большое фото на главной. Там же QR-код со ссылкой на меню и кнопка «Печать».
- Админка → **«Меню» → «Изменить»**: у каждой позиции можно указать описание и
  загрузить фото. Скрытые позиции гости не видят.
- Фото уменьшаются в браузере перед загрузкой и хранятся в `data/uploads/`
  (эту папку тоже включайте в резервную копию).
- Меню открывается только у гостей, подключённых к Wi‑Fi заведения. Если нужно
  открывать его через мобильный интернет, сервер надо разместить на хостинге.
- Админские запросы к API теперь требуют пароль администратора: гости в той же
  Wi‑Fi сети не могут менять меню, официантов и смотреть отчёты.

## Что нужно доделать до реальной эксплуатации

1. **Печать чеков на реальном чековом принтере.** Сейчас печать идёт через обычный
   диалог печати браузера — подходит для обычного принтера, настроенного как системный.
   Для термопринтеров по ESC/POS или подключения к фискальному регистратору (ККТ)
   нужен отдельный модуль — зависит от конкретной модели аппарата (когда определитесь
   с ней, доделаем интеграцию).
2. **Автозапуск сервера** при включении компьютера в кафе.
3. **Резервное копирование** файла `data/db.json` (например, копия раз в день на
   флешку/облако).
4. По желанию — перейти с файлового хранилища (`data/db.json`) на полноценную БД
   (PostgreSQL), если заказов станет много и нужна более высокая надёжность.

## Структура проекта

```
cafe-pos/
  server/
    server.js     — HTTP-сервер и API
    db.js         — хранилище данных (JSON-файл)
  public/         — веб-интерфейс (официант, кухня, админка, menu.html — меню для гостей)
  data/db.json    — данные (создаётся автоматически при первом запуске)
  data/uploads/   — загруженные фото блюд и логотип
```
